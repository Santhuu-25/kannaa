💡 Secure Coding Guidelines & Remediation Playbook

Actionable defensive engineering practices and verification procedures for Python application security.

🔐 Secrets & Key Management
  • Guidance: Never commit API keys, database credentials, or secret keys into source code repositories.
  • Remediation: Store credentials in environment variables or dedicated secret management systems (e.g. AWS Secrets Manager, HashiCorp Vault).
  • Verification: Run static analyzer to confirm no raw secret string literals are assigned to secret variable names.
🛡️ SQL Injection Prevention
  • Guidance: Avoid constructing SQL statements using string concatenation (`+`), `%` formatting, or f-strings.
  • Remediation: Use parameterized queries (`cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))`) or Object-Relational Mappers (ORMs) like SQLAlchemy.
  • Verification: Re-run static analyzer and verify all SQL execution calls pass parameters separately from statement templates.
⚡ Safe OS & Subprocess Invocation
  • Guidance: Avoid `os.system()` or `subprocess` calls with `shell=True`.
  • Remediation: Execute commands using `subprocess.run(["cmd", "arg1"], shell=False)` with argument lists to prevent shell metacharacter injection.
  • Verification: Confirm command arguments are passed as explicit string lists and `shell=True` is removed.
🔑 Secure Password Hashing
  • Guidance: Never use fast hash functions like MD5, SHA-1, or plain SHA-256 for storing user passwords.
  • Remediation: Use key-stretching salted hash algorithms such as PBKDF2:SHA256, bcrypt, Argon2, or scrypt (`werkzeug.security.generate_password_hash`).
  • Verification: Verify database user password fields store slow hashes with unique salt prefixes.
🎲 Cryptographic Randomness
  • Guidance: Do not use standard pseudo-random number generators (`random` module) for security-sensitive tokens.
  • Remediation: Use the Python `secrets` module (`secrets.token_hex(32)`) for session tokens, CSRF tokens, and password reset keys.
  • Verification: Audit all token generation functions to ensure `secrets` or `os.urandom` is used.
📁 Safe File & Path Handling
  • Guidance: Prevent Path Traversal (CWE-22) when reading or writing user-specified files.
  • Remediation: Strip path components using `os.path.basename(filename)` and verify canonical paths using `os.path.abspath()` within an allowed directory.
  • Verification: Test file paths with directory traversal payloads (`../../etc/passwd`) and verify access is rejected.
